# Implementation Plan: LLM Wiki Knowledge Brain

> Generated by `/PACT:plan-mode` on 2026-04-06
> Status: APPROVED

## Summary

Build an LLM-powered knowledge distillation system that processes Claude Code session data (2GB / 3,778 sessions / 55 projects) plus existing PACT memory stores into a curated Obsidian wiki. The system follows Karpathy's LLM Wiki pattern: Raw Sources → Distillation Pipeline → Wiki Pages, governed by a Schema Document. Phase 1 starts cheap by processing pre-distilled memory (pact-memory, agent-memory) before touching JSONL. The wiki is framework-agnostic plain markdown — PACT integration is an optional addon, not a dependency.

| State store | New | SQLite DB tracking processed sessions and wiki pages |

#### Design Approach
Three-layer architecture (Karpathy pattern):
1. **Raw Sources**: Claude Code JSONL sessions + pact-memory + agent-memory + project-memory
2. **Wiki**: Obsidian markdown pages with wikilinks, organized by page type
3. **Schema**: `wiki-schema.md` governing how LLMs read/write the wiki

Five-stage distillation pipeline:
```
Stage 1: Pre-Filter (local)   → Strip noise, credential scrub
Stage 2: Classify (Haiku)     → Score value, identify topics
Stage 3: Extract (Sonnet)     → Pull knowledge nuggets
Stage 4: Cluster (local)      → Group by topic, merge with existing
Stage 5: Synthesize (Opus)    → Generate/update wiki pages
```

Memory-first phasing: Process pre-distilled memory before raw JSONL to validate pipeline cheaply.

#### Key Decisions

| Decision | Options | Recommendation | Rationale |
|----------|---------|----------------|-----------|
| Pipeline language | Python, Node.js, Shell | **Python** | Best for data processing, native sqlite3, first-class Anthropic SDK |
| State management | SQLite, JSON watermark, Git | **SQLite** | Tracks lineage (session → extraction → page), supports queries, ACID |
| LLM mode | API-only, Interactive-only, Dual | **Dual mode** | Interactive: Claude Code does distillation (zero cost). Batch: API calls for scheduled/unattended runs. Pipeline supports both. |
| LLM tiering (batch mode) | Single model, tiered | **Tiered: Haiku→Sonnet→Opus** | Cheap classification, quality extraction, excellent synthesis |
| Wiki update strategy | Replace, Additive-only | **Additive-only** | Preserves manual edits, prevents regression |
| Vault restructuring | Full reorganize, Extend in-place | **Extend in-place** | Keep 05-Education/Coding-Notes/ structure, add new subfolders |
| Clustering approach | Topic matching, Embeddings | **Topic matching first** | Simpler, no external dependency; add embeddings later if needed |
| Dedup approach | Embedding similarity, Topic + title | **Topic + title matching** | Sufficient for ~100-150 pages; embedding dedup as Phase 4 if needed |

#### Interface Contracts

**Pipeline CLI**:
```bash
python wiki_pipeline.py run --sources memory-only    # Phase 1
python wiki_pipeline.py run                           # Full pipeline
python -m src.pipeline run --project "MyProject"      # Single project
python wiki_pipeline.py dry-run                       # Classify only, estimate cost
python wiki_pipeline.py estimate                      # Cost estimate
python wiki_pipeline.py status                        # Health report
python wiki_pipeline.py incremental                   # Process new sessions only
```

**Wiki page types**: entity, architecture, pattern, gotcha, workflow, comparison, synthesis

**Frontmatter extensions** (wiki-specific, on top of existing vault schema):
```yaml
wiki-source: auto | manual | seed
wiki-confidence: high | medium | low
wiki-sources:
  - {session-id-1}
```

## Risk Assessment

| Risk | Likelihood | Impact | Mitigation |
|------|------------|--------|------------|
| LLM extraction quality varies | HIGH | MEDIUM | Confidence scoring, `(unverified)` markers, Opus for synthesis, iterate prompts on 10 sessions first |
| Cost overrun | MEDIUM | MEDIUM | Per-run cap, dry-run mode, start with memory-only (Phase 1 costs ~$2-5) |
| Wiki bloat (too many low-value pages) | MEDIUM | LOW | Min 3 extractions per new page, value score gate (≥3), review flags |
| Existing seed pages overwritten | LOW | HIGH | Additive-only updates, `wiki-source` tracking, git rollback |
| Large sessions exceed context window | MEDIUM | LOW | Chunking with overlap at conversation boundaries |
| Sensitive data sent to LLM | MEDIUM | HIGH | Regex credential scrubbing before any API call, local pre-filtering |
| Pipeline runs while sessions are being written | LOW | LOW | 5-min stale window, JSONL is append-only (safe for partial reads) |
